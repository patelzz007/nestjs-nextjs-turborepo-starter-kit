## 2. The "can't push because of the pnpm 24-hour cooldown" problem — removed from CI

**Root cause:** `apps/mobile`'s `test` ran `expo install --check` **online**: it compares against the newest
patch Expo has published, while pnpm's `minimumReleaseAge` (24 h) refuses any release younger than a day.
After every Expo release, `test` (and therefore CI and the pre-push hook) failed for 24 hours with no
code change — 14, 16, 22 and 28 Oct.

**Fix (no workaround, pnpm's 24-hour supply-chain protection kept):**

- `apps/mobile` `test` → `jest && cross-env EXPO_OFFLINE=1 expo install --check`: it checks against the
  version table **inside the installed Expo SDK** — still fails on a real mismatch (wrong react-native,
  expo-camera …), never because Expo published something an hour ago.
- `pnpm check:expo-latest` (root and mobile): asks Expo's servers on demand; not part of any gate.
- Docs: `apps/mobile/README.md`, `docs/technical/mobile/mobile-app.md`.

**Found and fixed on the way (root cause):** `packages/ui-native` did not declare `metro`,
`metro-cache`, `metro-transform-worker`, so pnpm auto-installed Uniwind's metro peers there at floating
versions; mobile and ui-native then linked **two different copies of Uniwind**, and the theme-name type
augmentation (`uniwind-types.d.ts`) only applied to one (`skeleton.tsx`: `string` not assignable to
`"light" | "dark" | "nord"`). ui-native now declares the metro trio at the version Expo's bundler ships
(**0.87.1** — syncpack pins it so Uniwind's peers match the bundler Expo runs); both resolve one Uniwind.
