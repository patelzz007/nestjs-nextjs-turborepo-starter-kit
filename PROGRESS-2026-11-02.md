### 6. Security headers and a nonce-based CSP on web, admin and merchant — enhancements 1.3, 1.4

| | |
|---|---|
| **Problem** | The three Next.js apps sent no `X-Frame-Options` or CSP (only the API had Helmet), although `rules/10-security-auth-authorization.md` requires framing protection. Any site could frame the admin panel (clickjacking), and an injected `<script>` had nothing stopping it |
| **Added** | `@workspace/client/lib/security/security-headers`: one policy for all three apps. `withSecurityHeaders(request, routeRequest, options)` makes a fresh 128-bit nonce per request, continues the request with the CSP (Next.js reads the nonce from it and stamps every script it renders), and stamps every response, redirects included |
| **The policy** | `script-src 'self' 'nonce-…' 'strict-dynamic'` (no `unsafe-inline`, no `eval` in production); `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`; `connect-src` the API origin plus HTTPS/WSS (direct-to-storage uploads); images and media from HTTPS; `upgrade-insecure-requests` in production.
