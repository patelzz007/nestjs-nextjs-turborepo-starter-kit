# Boilerplate Roadmap

> [!NOTE] Ideas for making this **monorepo template** production-ready and pleasant to build on.
> This guide is about the _boilerplate itself_ (repo structure, tooling, DX, deployment,
> testing). Auth-specific ideas live in [auth-roadmap.md](./auth-roadmap.md).
>
> Note: product-heavy features like billing, i18n, webhooks, notifications, full-text search,
> and audit logging also appear in the **30 Boilerplate Features** section of
> [auth-roadmap.md](./auth-roadmap.md#30-boilerplate-features-make-the-template-whole) — this
> doc frames them from the boilerplate/DX angle instead.

---

## 🛠 15 Improvements (refine what exists)

### 1. Add real tests (the biggest gap)

There are only **two auto-generated NestJS spec files** (`auth.controller.spec.ts`,
`auth.service.spec.ts`) — and no test runner is wired through turbo (no root `pnpm test`).
Add a test runner per workspace:

- `packages/shared` → **Vitest** for Zod schemas (every schema gets valid/invalid cases)
- `apps/api` → **Jest** (Nest's default) for services/controllers with a mocked `PrismaService`
- `packages/client` → **Vitest** for `use-api`, `jwt`, `config` (pure logic, no DOM needed)
- Wire `"test": "vitest run"` / `"test": "jest"` scripts + a root `pnpm test` that runs them via turbo.

### 2. CI/CD pipeline

There is **no `.github/`** folder. Add:

- `.github/workflows/ci.yml` → on every PR: `pnpm install` → `pnpm lint` → `pnpm typecheck` → `pnpm test` → `pnpm build`
- `.github/workflows/deploy.yml` → on `main`: build + deploy web/admin (Vercel or any host) and api (Docker/S3/etc.)

### 3. Docker Compose for local dev

No `Dockerfile`s and no `docker-compose.yml`. Add:

- `docker-compose.yml` → PostgreSQL (+ optional Redis for future queues)
- `Dockerfile.api`, `Dockerfile.web`, `Dockerfile.admin`
- A junior can then run `docker compose up -d` and everything (DB included) is up.

### 4. Health endpoint that actually checks the DB

`GET /health` currently reports the DB status — but the check should ping the DB with
`prisma.$queryRaw\`SELECT 1\``and return`503`(with`db: "disconnected"`) instead of a
misleading `200`. Add an uptime field and an optional `deep` query param that also checks
Redis/S3 once those exist.

### 5. Structured logging

Replace the bare `console.warn` calls in `main.ts` with `NestJS` `Logger` (or Pino). Logs
should include the `correlationId` already generated by `CorrelationIdMiddleware` so a
request can be traced through the whole system. Add a `LOG_LEVEL` env var.

### 6. Fail-fast env validation for the API

`packages/shared/src/schemas/env.ts` already exports `EnvSchema`/`parseEnv` — but the API
**never calls it**. Call `parseEnv` in `main.ts` at startup so a typo'd `DATABASE_URL` or
missing secret crashes loudly with a helpful message instead of failing halfway through
bootstrap.

### 7. Uniform error response across the API

The `ResponseInterceptor` wraps successes, but errors come from many different exception
classes with inconsistent shapes. Add a **global exception filter** that normalizes every
error to the same `{ success: false, error: { message, statusCode, code? }, meta }` shape
(including validation errors from the `ZodValidationPipe`).

### 8. Reuse the response envelope in the FE types

The `envelope()` helper in `@workspace/client` already types `{ success, data, meta }`.
Extend it so the **shared** package exports one canonical `ApiResponseSchema`/error schema
that both FE and BE reference — no duplicated hand-rolled interfaces anywhere.

### 9. Environment variable documentation check

Each app has a `.env.example`, but nothing enforces that a real `.env` matches. Add a tiny
startup check (or lint rule) that warns when a required var is missing — saves hours of
"works on my machine" debugging.

### 10. Turbo task graph polish

`turbo.json` currently disables caching for everything and rebuilds `@workspace/shared`
before dependents. Add:

- a `test` task that runs after `^build`
- a `db:deploy` task (for CI)
- an explicit `dev` graph so `api`, `web`, `admin` start in parallel without blocking.

### 11. Editor/IDE consistency

Add `.editorconfig` (tabs, 2-space, UTF-8, LF) so editors that ignore `.prettierrc` still
format correctly. Optionally add `README` badges and a `CONTRIBUTING.md` so new contributors
know where things live.

### 12. Storybook for the UI package

`packages/ui` has 40+ shadcn components but no way to preview them in isolation. Add
Storybook (or a simple playground page) so components can be developed and visually
reviewed without spinning up the full apps.

### 13. Runtime checks (Zod) on API responses in the FE

`use-api` can `.parse()` responses with a response schema. Turn this on for a few critical
endpoints in dev mode (`NODE_ENV !== "production"`) so a BE/FE contract drift is caught
immediately instead of as a confusing runtime bug.

### 14. Prisma script consistency ✅ Done

`db:migrate`/`db:seed`/`db:generate` exist but are scattered. Standardize on:
`db:deploy` (migrate deploy), `db:reset`, `db:studio`, and make `db:seed` idempotent
(`upsert` instead of `create` where possible) so re-running it never throws.

**Implemented** — `db:deploy` is now the canonical migrate-deploy script (alias
`db:migrate:deploy` removed) in both `apps/api` and the root; `db:migrate:status`
was added as a root shortcut. `db:seed` now wipes the volatile demo tables
(refresh tokens, clicks, API keys, usage logs, reset tokens) at the start of
`main()` before re-creating them, while reference data (permissions, roles,
users, tags, URLs, menu items) stays on `upsert`. Re-running converges instead of
accumulating or throwing — verified by running the seed 3× against a live DB.
**Every `db:*` script is also wired as a turbo task** (`pnpm turbo run db:<task>`
— all run exactly once in `apps/api`): `db:seed` depends on `db:generate` +
`db:deploy`, `db:reset` depends on `db:generate`, `db:migrate*` are
`interactive`, and `db:studio` is `persistent`.

### 15. Dependency hygiene ✅ Done

Pin the exact same versions of shared deps (React, Zod, TS) across workspaces — a
`syncpack` config or a simple script that fails CI when versions drift. This prevents
"works in web, breaks in admin" type bugs.

**Implemented** — added `syncpack` (v15) with a root `.syncpackrc.json` that
(a) enforces `sameRange` for `react`, `react-dom`, `zod`, `typescript`, `next`
and (b) pins `react`, `react-dom`, `zod`, `typescript` to **exact** versions.
`zod` and `typescript` were pinned to `4.4.3` / `6.0.3` (no caret) across every
workspace. The commands live in **`packages/tooling`** and are wired as **turbo
tasks** — `pnpm deps:check` (fails on drift — CI-ready), `pnpm deps:fix`
(auto-aligns), `pnpm deps:list` (prints versions); root `pnpm deps:*` scripts
delegate to `turbo run deps:*`. See [dependencies.md](./dependencies.md).

## 🚀 15 New Features (expand the boilerplate)

### 1. Multi-tenant organizations (implement the design)

The full design already exists in [auth-roadmap.md](./auth-roadmap.md) (`Organization`
model, `organizationId` FK, tenant middleware, Prisma auto-scoping, real org name from env).
**Implement it** so the template ships tenancy-ready out of the box.

### 2. Secrets management UI (implement the design)

Also designed in auth-roadmap: `Secret` + `SecretAuditLog` models, AES-256-GCM encryption,
SuperAdmin-only `/admin/secrets` endpoints, and an admin panel page. Ships the "rotate
Resend key without redeploying" feature users actually want.

### 3. File uploads (S3 / R2 / MinIO)

Add a `Media` model + `POST /uploads` that returns a **presigned URL** (never stream the
file through the API). Works with AWS S3, Cloudflare R2, or MinIO via one env-switchable
client. Include avatar upload in the profile page as a reference implementation.

### 4. Background jobs (BullMQ + Redis)

A `QueueModule` with an email queue (verification, password reset, account-locked) and an
export queue. Add `docker-compose` Redis, `@nestjs/bullmq`, and a small admin page showing
failed/retried jobs. Emails stop blocking the request cycle.

### 5. Real-time notifications (SSE / WebSockets)

`Notification` model + a NestJS Gateway (or SSE endpoint). The web/admin apps get a bell
icon with unread count, `PATCH /notifications/:id/read`, and a "mark all read" action.
Events: login from new device, account locked, export ready.

### 6. Webhook system

Let users register webhooks (with a signing secret) that fire on `url.created`,
`click.recorded`, etc. `Webhook` + `WebhookEvent` models, HMAC signature verification,
exponential-backoff retry, and a delivery log endpoint.

### 7. Full-text search

Postgres `tsvector` + `GIN INDEX` on searchable columns (URLs, tags, users). A unified
`GET /search?q=` endpoint returning typed results, plus a search box in the admin panel.

### 8. Audit log (full system)

A `AuditLog` model + Prisma `$use` middleware that records every mutation (actor, action,
resource, before/after JSON, IP). A read-only SuperAdmin page. Essential for SOC 2 and
answering "who changed what and when".

### 9. Feature flags

`FeatureFlag` model (key, enabled, orgId?, rolloutPercentage?) + `FeatureFlagService`.
A SuperAdmin UI to toggle features without redeploying, and an A/B rollout knob per org.

### 10. OpenAPI client SDK generation

Generate a typed client (`@workspace/api-client`) from the Swagger document so FE code can
drop the hand-written `use-api` procedures for generated ones (or at least auto-check them
in CI with a diff). Keep the current Zod-based registry as the source of truth and generate
from it — no drift between docs, BE, and FE.

### 11. E2E test suite (Playwright)

`tests/e2e/` with the critical paths: signup → verify → login → create URL → logout, plus
admin login rejection for non-admin users. Seed a known user, reuse auth cookies for
authenticated flows. This is the single highest-confidence guard the repo is missing.

### 12. Internationalization (i18n)

`next-intl` on web/admin and `@nestjs/i18n` on the API. Move user-facing strings (login
form, emails, error messages) into locale files. Start with `en` + `ms` given the repo's
audience, but structure it so adding locales is a config change.

### 13. Data export / import

`POST /exports` (CSV/Excel of URLs, clicks, or users) processed in the background and
emailed a signed download link. Bulk URL import via CSV upload. Complements the existing
pagination everywhere.

### 14. Subscription & billing (Stripe)

`Subscription`, `Invoice`, `Price` models + Stripe checkout/webhooks, synced with the
`plan` field already on `User`/`Organization`. Handles trial, active, past_due, canceled.
A billing page in admin and a plan-gating middleware.

### 15. Admin analytics dashboard

The API already records `Click`/`UsageLog` data and `packages/ui` already ships a chart
component. Build the reference dashboard: total clicks, clicks per day (line chart), top
URLs (table), referrers (pie chart) — all mobile responsive, all reading from existing
endpoints. This is the "wow" page that proves the template end-to-end.
