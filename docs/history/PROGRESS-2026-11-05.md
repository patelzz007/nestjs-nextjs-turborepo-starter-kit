# Progress — 4 → 5 Nov 2026: the docs site on TanStack Start

The request: move the docs and blog site (`apps/docs`) from Astro to TanStack Start, using every TanStack
library that fits, redesigned to production quality ("B + F Plex": the drafting-grid layout, graphite and
verdigris, IBM Plex, the guide's cover as a band, a "Focus timeline" table of contents, the shared Alert
redesigned as "Tile"). This is phase 1 of `docs/architecture/notion-docs-plan.md`.

**Nothing is committed or pushed.** Another session is working on the mobile app at the same time; this work
did not touch `apps/mobile` or `packages/tokens`.

---

## What was built

| Part | What changed | Why |
|---|---|---|
| `packages/docs-renderer` (new) | The markdown plugins, code-block, media and API-reference code moved out of `apps/docs` unchanged, with their tests; a `createMarkdownRenderer` pipeline; heading ids; callouts rendered with the shared `Alert` | The renderer is reused by phase 2 (Notion) and is testable on its own |
| `apps/docs` | A pre-rendered TanStack Start app: Router (typed routes, server routes for the feed, robots, search index), Query (search and endpoint indexes), Table (the shared `DataTable` for endpoints), Pacer (search debounce), static server functions | The plan's phase 1 |
| Regression baseline | `regression-baseline/` captured from the Astro build: 214 pages and 94 files, each page's title, h1, sharing image and anchors, plus 12 search queries; checked on every build | So the move loses no page, link or anchor |
| Shared `Alert` ("Tile") | Neutral card, solid icon tile, default icon per variant; long titles and code no longer overflow | The old one read as generic; used by web, merchant and admin too |
| Shared `DataTable` | `toolbarLayout="fill"`: search and filters as equal columns across the row | The endpoints toolbar |
| Shared filter options | An optional `icon` per choice (`FilterOption`); when a filter's choices have icons, "All" gets one too, so the labels line up | The endpoints' Access and Group lists were text only |
| Endpoint filters | Access: globe, sign-in, key, cookie. Group: each API reference page's own icon, which the guide tree now shows too | Easier to scan the 20 groups |
| Home page | Cover pictures: a picture grid in the hero, a cover strip on every guide card, tinted pills for each guide's first sections | The page was all text |
| Light theme | Cool neutral canvas (`#f1f4f9`), chrome a shade lighter, never pure white | The warm paper tone was hard on the eyes |
| Scrolling | Jumps to a heading glide (not for reduced motion); the timeline follows; page changes stay instant | In-page jumps were instant |
| Themes | Light and dark only; the apps' Nord is no longer offered on the docs (a stored "nord" falls back to the OS) | Nord had no docs palette and looked broken |
| Shared `CodeBlock` rows | One `code-block-line` utility per row instead of the ~2,600-character class list; computed styles identical in 56 row states | 27 MB of the docs build; also lighter in web, merchant and admin |

## Bugs found and fixed at the root

| Bug | Root cause | Fix |
|---|---|---|
| Build 237 MB | Each article body was in the loader data, so serialised two or three times per page | Body stays in the HTML only; on client navigation it is read from the page's own pre-rendered HTML |
| Build failed on a busy machine ("fetch failed") | The pre-render server bound `localhost`, which macOS gives IPv6 `::1` only; `fetch` tries `::1` then `127.0.0.1` with 250 ms each, so under load `::1` timed out and `127.0.0.1` refused | `preview.host: "127.0.0.1"`: one address, nothing to fall back to. Also kept: renders run one at a time with a turn of the event loop between them, added before the real cause was found; with it the server's longest stall while rendering all 205 guides measures 1.3 s (not measured without it) |
| Flaky skeleton test | The fetch stub answered at once, so on a fast run the skeleton was gone before the test looked | The test releases the response itself; 5 runs in a row pass |
| Duplicate React key while a page loads | The skeleton lines were keyed by width, and `w-full` repeats | Each line has its own id; regression test |
| Hydration warnings | Island race (React runs effects twice in dev) and a browser extension's body attribute | Cancellable island mounting; `suppressHydrationWarning` on `<html>`/`<body>` only |
| Callout overflow | The Alert's description grid track was `auto` | `minmax(0, 1fr)` in the shared Alert |
| Lost anchor on the TypeScript guide | The heading was renamed when TypeScript 6 stopped applying to the docs | Recorded in `RENAMED_ANCHORS`; the baseline accepts it only if the new anchor exists |
