## How a component is ported

1. Native component exists (or is extended / built in `packages/ui-native`, with its test) — kit contract: memo + forwardRef, cva, tokens only, no inline literal props, own test.
2. Examples: `examples/<slug>/<slug>-N.tsx` exporting `<Pascal>NExample` (one per web feature, same file names); helper scripts in the session scratchpad (`exgen.py`, `manifest.py`).
3. `features.json`: the web's ids, labels, files and exports; descriptions adapted to a phone.
4. `guidelines.json` + `<slug>-do-N.tsx` / `<slug>-dont-N.tsx` (at least 2 pairs).
5. `overview.md` + `docs.md` (one `showcase-api` block; `showcase-example` ids that exist).
6. `pnpm tools mobile:showcase`, then `jest src/features/showcase` (every example renders).

## Bug: the drawer's Showcase item did not navigate

- Symptom: pressing Showcase in the drawer left the person on the screen they were on; opening `/showcase` directly fell back to `/`.
- Root cause (reproduced in `app-drawer.test.tsx`): `src/app/(app)/showcase` sits directly in the (app) tab navigator but was not declared as a `Tabs.Screen`. In this expo-router version the tab navigator only preloads an undeclared route — it never focuses it (`href: null` behaves the same). The old `/settings/components` lived inside the Settings tab's stack, so it never hit this.
- Fix (owning layer, navigation config): `APP_UNTABBED_SCREENS` in `features/navigation/app-tabs.ts` lists the (app) routes with no tab button; the tabs layout declares them. The tab bar already shows only `APP_TABS`.
- Regression test: "opens the showcase from the Developer section" (drawer → Showcase → `/showcase`).
- Follow-up: a tooling guard that every folder in `src/app/(app)` is declared (the mobile tests may not read the file system).
