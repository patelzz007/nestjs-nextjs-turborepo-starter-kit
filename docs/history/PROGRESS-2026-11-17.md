# Progress: 2026-11-17

## Customer tiers (ADR 085)

Agreed in a design session on 2026-11-13 and built today. Tiers are behind the `customer-tiers` flag, on by default. The mobile app is unchanged: the feed hides locked rewards unless the client asks for them.

| Area | Change |
| --- | --- |
| Database | `CustomerTierStanding`, `CustomerTierChange`, `CustomerTierSettings`; `Reward.minimumTier`; `RewardRedemption.customerTier` (the tier at that moment). Folded into the regenerated init migration `20261117063631_init` (the baseline marker moved to it), RLS `67-customer-tiers.sql`, 3 system operations |
| API: tiers context | Window policy, standing aggregate (promotion, hold, warning, demotion), evaluation after each checkout (after-commit), nightly review at 03:00 Malaysia time, settings with a reason, tier page, admin reads, notices, personal-data export and erasure |
| API: other contexts | Rewards: minimum tier on create and revise, changeable on a live reward without re-review, refused with chosen customers or referrals. Claims: 403 below the tier, nothing held. Pos: the tier snapshot and `customerTier` on the till's preview. Reporting: redemptions by tier |
| API: feed | `includeLocked=true` lists locked rewards after the claimable ones on every page (`fetchSegmentedPage`, offset pages only). `GET /tiers/availability` also gives the caller's tier |
| Web | Locked rewards in the feed with a lock badge and "Hide locked", unlock progress on the detail page, the tier in the header, the "My tier" page |
| Merchant | Minimum tier in the editor and on a live reward, customers' tier in the picker, redemptions by tier in analytics |
| Admin | Settings → Customer tiers (changed with a reason), a customer's tier and history on their page, customers by tier on Analytics |
| Shared UI | `TierBadge`, `MinimumTierSelect`, `useTiersEnabled` and the per-tier share bar in `packages/client` |
| Seed | Tier rules, minimum tiers on 3 rewards, standings replayed through the aggregate, one customer with a pending warning and one demoted |
| Docs | ADR 085 accepted, glossary, context map, RLS system operations, list queries |

Also fixed on the way: the reward inventory port dropped `holdsUnit` when reserving, so a claim that already held a unit was refused when stock ran out. A regression test covers it.

Known gap: the development seed has no Diamond customer. Its history spans two merchants, and Diamond needs three under the default per-merchant cap.
