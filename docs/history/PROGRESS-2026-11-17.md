## Fixed along the way

| Problem | Fix |
|---|---|
| Experiment update would send `key`/`configKey` to a strict schema | The update payload names only the plan's own fields |
| Rule forms typed branded timestamps as form input | Forms hold `*Input` types; the schema brands them |
| Admin Releases UI used inline handlers (lint) | Small row components and `useCallback` throughout |
| Bundle hit the per-IP `strict` throttler (429), so flags read as off and parallel sessions refreshed one token (theft) | Bundle and stream skip `strict` (page-load reads); `default` and `preAuth` still count them |
| Network rewards published without an image (catalogue 500) | Each new merchant uploads its own copies of three covers; every reward links one |
| Network visitors included the e2e test accounts and the tier cast | Visitors are the other active extra customers only |
| Flag building blocks were `.strict()` inside responses (ADR 022) | Open objects (unknown keys stripped); request wrappers stay closed |
| Migration name ended in a digit (restore drill) | Renamed `20261117210000_feature_flags_rules_and_experiments`; later folded into the regenerated init `20261117181407_init` (twenty-third pre-release reset, `migrations-baseline.json` moved) |
| Seed coverage: 7 tables never soft-deleted | Reviewed `never-soft-deleted` entries |
| Docs baseline lost the v1 anchors | Mapped in `RENAMED_ANCHORS` to their v2 successors |
| Bundle budgets: new Releases routes, +1–5 KiB on 13 pages | New routes at measured + 10%; raised pages at measured, rounded up to the KiB |
| Local `test:e2e`: the last suites' `app.close()` hung 30 s | The local broker lacked the new `platform.feature-flags` topic, so the producer waited out `message.timeout.ms` on shutdown; `kafka:provision-topics` created it (docs already require it) |
