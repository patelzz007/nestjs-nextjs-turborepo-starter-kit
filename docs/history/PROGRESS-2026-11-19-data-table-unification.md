## Decisions (made by the implementer under D12; for owner review)

| # | Decision | Why |
|---|---|---|
| I1 | Engine files were **moved** with `git mv`, not copied (plan step 1.1 said copy). | A copy would be 10,000 new lines plus 10,000 deleted lines with no history. A move keeps `git log --follow` and shows the owner only the real changes. Cost: the old `data-grid` showcase is broken between phase 1 and phase 5 (nobody sees it; one sitting, no commits). The old `DataTable` (the one real pages use) stays untouched until phase 7. |
| I2 | Engine file names keep a `table-engine-` prefix (`table-engine-table-body.tsx`), not the bare names in plan 3.4 (`body.tsx`). | Lets one mechanical rename fix every relative import; a bare `table.tsx` / `core.tsx` would need hand edits in every file. |
| I3 | Engine copy stays its own label family, `tableEngine`, shared by `DataTable` and `Spreadsheet`. `DataTable`'s `labels` prop takes overrides for both `dataTable` and `tableEngine` keys in one flat object (no key is in both families). | Plan 3.11 said "merge into `dataTable` and add a `spreadsheet` family". Both public components need the engine copy, so one shared family avoids duplicating 35 strings × 4 languages. |
| I4 | `ui-kit-logic` exports for the engine are renamed `TableEngine*`; the old `DataGrid*` names survive only as aliases in `src/data-grid/index.ts` until Part C. | The native kit still imports the old names. |
| I5 | Real usage found in phase 0.2: 17 admin components + 1 docs component render `DataTable` (the plan said 19 files; 3 of the operations files import it without a JSX block at the top level, see Appendix B). No real page uses inline edit, row drag, virtualisation or column pinning. | Sets the migration order by real props. |
