## Done

| Area | What |
|---|---|
| API versioning | A version belongs to one endpoint, and a newer version inherits every route it does not replace. `@ApiController(path)` + `@SinceApiVersion("v2")` replace `@Controller(apiPath(...))` on 94 controller files; every route answers at `/api/v1/…` and `/api/v2/…`. Client pin (`ApiClientConfig.apiVersion`) and per-call override (`Accept-version`, marked `(override)` in the access line). One Swagger document per version, the docs gate covers each one, `operationId` stays `Controller_method`. The `onRequest` `Accept-version` rewrite was dead (Fastify had already routed) and is gone. |
| Forwarding files | 11 re-export-only files removed; importers point at the real source (`@workspace/messaging/nest`, `@workspace/api-client/testing`, `@workspace/shared`). |
| Dead code | Unused files, exports, types and dependencies removed after a repo-wide search for each (knip report + string search). Seven API dependencies, `nest-cli.json`, and unused frontend dependencies (`date-fns`, `next-themes`, `recharts`, `zustand` where unused). |
| Line noise | 31 stale file-banner paths fixed. All 58 `return await` are inside `try` blocks (kept); no real TODO markers. |
| Duplication | `RedisBroadcastChannel<TMessage>` replaces two hand-rolled Redis pub/sub channels (feature-flag catalog version, in-app notifications); one shared `FakeRedis` for the specs. |
| Reads (D1) | Owner's decision after the first premise was withdrawn: change the rule, then convert ([ADR 096](../adr/096-single-port-reads-are-application-services.md); `rules/23`, migration plan §4.4 and §7). 64 of the 119 query handlers read through one collaborator and are now application-service methods: 23 new `*ApplicationService` classes across audit, authorization, claims, identity, integrations-github, kanban, notifications, referrals, rewards, tenancy and inbound webhooks. The 55 that compose collaborators (merchant access, exports, sign-in crypto, role-assignment preview) stay Query + QueryHandler. A precondition on the actor moved into the method unchanged, and those methods are `async`, so a refusal is still a rejected promise. No endpoint, response, authorization decision or SQL changed. |
| Docs | ADR 094, architecture §6, `http-server.md`, `errors.md`, `routes.md`, `api/README.md`, `dos-and-donts.md`, `adding-a-feature.md`, `tooling/oxlint.md`, `authorization/backend.md` §11.1 (commands, `@CurrentActor`), `rules/02`, `rules/05`, `rules/21`, `rules/24`. ## Found along the way

| Problem | Fix |
|---|---|
| CI "Apply migrations + RLS" failed: the security apply read the whole API config, and that job has no API `.env` | `readDatabaseToolEnv()`: the database tools need only `DATABASE_URL` (+ `NODE_ENV`). 8 tests. |
| A queue job in flight at `app.close()` failed with "Cannot use a pool after calling end on the pool" (seen in the OpenAPI export and twice in the e2e run). Only the SIGTERM path was protected, by a separate worker drain. | Owner's decision: `app.close()` must finish the work first, fixed at the root ([ADR 095](../adr/095-shutdown-finishes-work-before-closing-connections.md)). Connection owners (Prisma ×2, Kafka producer, idempotency lock pool) close in `onApplicationShutdown`; every `@Cron` declares `waitForCompletion` (guard spec); interval schedulers and the maintenance registry await their runs (`InFlightWork`); the exposure buffer flushes after the HTTP server closed. `BullMqWorkerDrainService` removed. |
| While closing, a request already in its handler answered on a keep-alive connection that held the server open for 72 s (Fastify's `keepAliveTimeout`); an open event stream held it open until the shutdown timeout | `registerHttpShutdown`: `Connection: close` and idle-socket close while closing, and every `@Sse()` stream ends on `HttpServerClosing`. e2e: 72 s → 1.8 s, and an open stream ends in 0.35 s. |
| `public-operation-coverage` timed out in full runs (15 s hook timeout; 1.2 s alone) | Importing every controller is a module-graph load and ran inside `beforeAll`. Both coverage specs now load it at the top level, outside any hook timer. |
| `onRoute` still set a `rateLimit` config for `@fastify/rate-limit`, removed earlier (ADR 071) | Removed; the docs no longer describe a limit keyed by IP + API version. |
| Comments named `prisma/rls/*.ts` files that live in `prisma/security/` | Fixed, and the orphaned JSDoc in `apply.ts` moved onto `applyRowLevelSecurity`. |
